## 2. 启动与 iPad Safari 打开

### 2.1 最快方式：电脑局域网 HTTP

在电脑上执行：

```bash
cd /workspace/dsh-projects/gongkao-cuoti
python3 serve.py
```

终端会打印类似：

```text
本机访问：   http://127.0.0.1:8080/
iPad 访问：  http://192.168.1.23:8080/
```

操作步骤：

1. iPad 与电脑连接**同一个 Wi-Fi**。
2. iPad Safari 地址栏输入终端打印的 `iPad 访问` 地址（形如 `http://192.168.x.x:8080/`）。
3. 首次打开建议：Safari 分享按钮 → **添加到主屏幕**，以后从主屏幕打开。
4. 若打不开：确认电脑防火墙允许 8080 端口；确认没有连到访客 Wi-Fi / 手机热点隔离网络；在电脑上用浏览器访问 `http://127.0.0.1:8080/` 自检。

> 本 V1 没有固定公网地址，也**不需要 token**。地址由启动脚本按当前局域网 IP 打印。
> 首次启动若端口被占用，可换端口：`python3 serve.py --port 9000`，iPad 地址同步改为 `http://电脑IP:9000/`。

### 2.2 HTTPS：需要完整离线缓存 / 主屏幕 PWA 时

Service Worker 只在安全上下文（HTTPS 或 localhost）可用。普通局域网 HTTP 下，**页面打开后断网仍可继续查看和记笔记**，但关掉标签页后重新打开需要网络。

需要“断网后重新打开也能用”时：

```bash
python3 serve.py --https --port 8443
```

首次启动会在临时目录生成自签名证书，并打印路径（Linux/macOS 通常类似 `$TMPDIR/gongkao-cuoti-cert/cert.pem`）。iPad 打开 `https://电脑IP:8443/` 后：

1. 出现“此连接非私人连接”提示时，点 **显示详细信息 → 访问此网站**，输入锁屏密码继续。
2. 若只求立即使用，做到这一步即可；数据、拍照、分析都能用。
3. 若要让 iOS 完全信任证书并启用 Service Worker 离线缓存：
   - 把终端打印的 `cert.pem` 通过 AirDrop / “文件”App 传到 iPad；
   - 在 iPad 上点开证书文件，按提示安装描述文件；
   - 打开 **设置 → 通用 → VPN 与设备管理**，确认已安装；
   - 打开 **设置 → 通用 → 关于本机 → 证书信任设置**，为 `gongkao-cuoti.local` 打开完全信任；
   - Safari 重新打开 HTTPS 地址。
4. 若路由器/电脑 IP 变化，证书里的 IP 会失效，需要删除临时证书目录后重新生成，或在 iPad 重新信任新证书。

更省事的替代方案（可选，不属于 V1 代码）：

- 用自己已有的受信任 HTTPS 证书：`python3 serve.py --https --cert 证书.pem --key 私钥.pem`
- 放到任意支持 HTTPS 的静态托管（GitHub Pages、Cloudflare Pages 等免费静态托管均可）；
- 用 Tailscale / Caddy 等提供可信 HTTPS。

> 不要把本服务直接暴露到公网。本 V1 无账号体系，设计前提是“仅自己、可信局域网”。

### 2.3 “云端启动”

本项目是纯静态网页，没有服务端接口依赖。把整个目录上传到任意静态文件服务器（需 HTTPS 才能启用完整离线缓存）即可；启动命令也可用：

```bash
cd /workspace/dsh-projects/gongkao-cuoti
python3 -m http.server 8080
```

数据仍然只存在**打开网页的那台 iPad 的浏览器**里，不会因为换服务器而同步。

## 3. 账号与密钥

### 3.1 账号

**不需要账号，也没有登录。** 仅自己使用，数据存在 iPad 浏览器本机。

### 3.2 默认分析：本地规则（0 元、离线）

- 默认“分析方式 = 本地规则”。
- 保存题目时立即分析，输出考点、错因标签、原因判断和复盘动作。
- 不发送任何内容，不联网，不产生费用。
- 规则覆盖：知识缺失 / 审题偏差 / 方法不当 / 粗心失误 / 时间不足 / 心态波动 / 信息不足。

### 3.3 可选：联网 AI（OpenAI 兼容接口）

在 **设置 → 分析方式 → 联网 AI** 填写：

| 字段 | 说明 |
|---|---|
| 接口地址 | 可填空到 `/v1`，也可直接填完整的 `/v1/chat/completions` |
| 模型名称 | 如 `qwen2.5:7b`、`gpt-4o-mini`（由你配置的服务决定） |
| API Key | 可选；本地 Ollama 通常留空 |

示例（电脑上运行 Ollama，让 iPad 访问）：

```text
接口地址：http://192.168.1.23:11434
模型名称：qwen2.5:7b
```

Ollama 默认只监听本机，需要允许局域网访问并放行浏览器跨域，例如启动时：

```bash
OLLAMA_HOST=0.0.0.0 OLLAMA_ORIGINS='*' ollama serve
```

（具体参数以你安装的 Ollama 版本为准；把 `*` 换成限定来源更安全。）

行为说明：

- 切换到联网 AI 后，保存题目会先完成本地分析，再在联网可用时自动尝试 AI 分析并覆盖展示。
- 在题目详情点“重新分析”也按当前设置执行。
- 联网失败（超时、CORS、接口报错、离线）会自动保留本地分析，并在分析卡片里显示失败原因。
- **只发送文字**：题干、我的答案、正确答案、自评错因、已标注考点；图片、附件始终留在本机。
- API Key 只存本机 IndexedDB；导出备份时会主动清空，不会写进 JSON。
- 若接口不支持浏览器跨域（CORS），会回退本地规则。这是浏览器限制，不是应用崩溃。

> 本 V1 不内置任何付费 API，也不附带密钥。是否接入、接哪家，由使用者自行决定。

## 6. 数据、备份与隐私

### 6.1 存在哪

- 浏览器 **IndexedDB**，数据库名 `gongkao-cuoti`。
- 对象仓库：`questions`（错题/分析/笔记/复习状态）、`maps`（导图节点）、`files`（图片/PDF 二进制）、`meta`（设置）。
- 图片在入库前会压缩到最长边 1600px、JPEG 0.84（小于 700KB 的图片和 SVG/GIF 保留原样）。
- 没有服务器数据库，没有账号，没有跨设备同步。

### 6.2 备份

**设置 → 数据与备份 → 导出备份** 会下载一个 JSON，包含题目、导图、附件（base64）和设置；**不包含 API Key**。

**导入备份** 按 id 合并：

- 已存在的题目/导图跳过，不覆盖；
- 只新增缺失数据；
- 不删除现有内容；
- 适合换设备、清理 Safari 数据前留底。

### 6.3 数据安全提醒

- 在 iPad 上 **清理 Safari 网站数据 / 删除主屏幕图标并清除数据** 会清空 IndexedDB。重要数据请先导出。
- **不同访问地址是不同存储空间**：`http://IP:8080`、`https://IP:8443`、不同端口或不同域名，Safari 会视为不同网站，数据不互通。决定用 HTTPS 后建议一开始就用 HTTPS 录入；若已用 HTTP 录过，先导出备份，在新地址导入。
- 浏览器无痕模式可能限制 IndexedDB，请用普通模式。
- “归档”不是删除；V1 没有硬删除按钮，也没有“清空全部数据”按钮。
- 局域网 HTTP 没有登录，同一 Wi-Fi 下知道地址的人可打开页面；不要把端口映射到公网。

## 8. 已知边界（V1 不扩范围）

1. **不做图片 OCR**：导图节点来自已有错题的考点自动生成，或手动添加；不会读取导图图片里的文字，也不会在图片上画坐标点。这是 V1 最明确的简化。
2. **不做坐标级导图对齐**：薄弱点以节点清单 + 红/黄点展示，不做图上覆盖连线。
3. **不做后台推送/闹钟**：复盘提醒只在应用内（首页、导图页、复习页）显示，不发送系统通知。
4. **不做多设备同步/账号/多人**：数据不离开本机浏览器，换设备用导出/导入。
5. **不做原生 App / App Store 包**。
6. **不做题库爬取、付费题库、付费订阅**。
7. **不做硬删除**：题目只能归档/恢复；导图节点可删，但不删错题。
8. **HTTP 局域网下无 Service Worker**：页面开着时断网可继续用；关掉后重开需要网络。完整离线需要 HTTPS（或 localhost）。
9. **AI 分析只发文字**：不发送图片；不内置视觉模型。
10. **无固定公网地址/无 token**：URL 由启动脚本打印；公网部署需自行加 HTTPS 与访问控制。

## 9. 常见问题

| 现象 | 处理 |
|---|---|
| iPad 打不开地址 | 确认同一 Wi-Fi、电脑防火墙放行端口、没用访客网络；先电脑自测 `http://127.0.0.1:8080/` |
| 端口被占用 | `python3 serve.py --port 9000`，iPad 用新端口 |
| 拍照按钮没反应 | Safari 需相机权限；拒绝权限时改用“相册 / 文件” |
| 页面提示数据库打开失败 | 不要用无痕模式；关闭旧标签页后刷新；Safari 设置里确认网站数据未被完全禁用 |
| 离线重开打不开 | 普通 HTTP 没有 Service Worker；改用 `--https` 并信任证书，或先保持页面打开 |
| HTTPS 提示不安全 | 自签名证书正常现象；按 2.2 信任，或换可信证书/静态托管 |
| 联网分析失败 | 检查接口地址、模型名、API Key、CORS、iPad 是否能访问电脑端口；失败会自动保留本地分析 |
| 更新后仍是旧页面 | 刷新；必要时 Safari 设置里清除该网站缓存，或重新添加到主屏幕 |
| 担心数据丢 | 定期“设置 → 导出备份”；清理 Safari 数据前务必导出；换 HTTP/HTTPS、端口或地址前后先导出/导入 |
